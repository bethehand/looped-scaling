## 方法要点
从 Kaplan 设定出发逐项修正，直到复现 Hoffmann（Chinchilla）律，每步给出 N*(C) ∝ C^a 的指数（Table 1，括号为 95% CI；RefinedWeb / OpenWebText2）：
1. **复现 Kaplan（§3.1）**：batch 2^19 tokens；warmup 3000·2^19 ≈ 1.57B tokens；cosine 在 2.5×10^5·2^19 ≈ 131B tokens 衰到 0；N 取 N_Kaplan = 不含输出头（N − d·v）。a = 0.835 (0.82, 0.85) / 0.864 (0.82, 0.90)；ρ* 范围 (8, 1536) / (5, 2617)；N*(C_C) = 3T (3T, 4T)（Fig. 1a，C_C = 5.88×10^23）。Kaplan 原律 1.6×10^9·(C/8.64×10^19)^0.88。
2. **计入输出头 FLOPs（§3.2）**：改用 N = 全部线性层含 head。a = 0.706 (0.69, 0.72) / 0.699 (0.66, 0.72)；N*(C_C) = 787B (630B, 916B)。"switching to our model size count also reduces the exponent a by more than 0.1"。不计 head 的 FLOPs 低估 "from roughly 10% at larger models to roughly 90% at smaller models"（Table 2：5M 模型 −93.5%，901M 模型 −8.41%）。
3. **修正 warmup（§3.3）**：把 warmup token 数设为 **等于参数量 N**。a = 0.602 (0.59, 0.62) / 0.603 (0.57, 0.63)；N*(C_C) = 292B (249B, 355B)。原因："for smaller-scale models, the optimal number of tokens as a function of compute is less than or close to the number of warmup tokens"；修正后 "the optimal number of tokens is always at least 5 times greater than the (interpolated) duration of the warmup period"（Fig. 2）。消融（App. F, Table 5，108M，~2.1B tokens，σ = 0.002）：N/4 3.546、N/2 3.542、**N 3.532**、2N 3.528、4N 3.536、8N 3.543、16N 3.586。
4. **按预算设置 cosine 衰减（§3.4）**：对网格中每个 FLOP 值取 7 个 ρ ∈ [1, 100] 的模型，cosine 衰到峰值 1%，warmup = min(N, 20% 总 token)。a = 0.571 (0.56, 0.59) / 0.574 (0.54, 0.61)；R² 0.993 → 0.998；N*(C_C) = 183B (152B, 240B)。"most of the gap remains"；成本 "roughly twice as expensive"。终值消融（Table 6）：0.001× 3.444、0.01× 3.442、0.1× 3.440（"barely impacted"）。Kaplan 的 131B 周期在其算力下 "less than 1.5% decay"。
5. **按规模调 batch、LR、β2（§3.5，常数 LR、无衰减）**：a = 0.497 (0.49, 0.50) / 0.518 (0.49, 0.54)；ρ* 范围 (14, 16) / (11, 22)；N*(C_C) = 77B (70B, 86B)；"the scaling exponent matching 0.5 to within 0.6% and the predicted model size at Chinchilla compute within 15% of Chinchilla's size"。
6. **复现 Kaplan 修正律 0.73（App. H）**：保留调好的超参、恢复 head 不计与长 warmup：a = 0.717 (0.71, 0.72)（对照 Kaplan 修正律 1.3×10^9·(C/8.64×10^19)^0.73）。
- **超参扫描（App. G）**：6 个模型 5M–221M（主体 5M–108M，220M 用于验证），扫 LR × batch × β2 ∈ {0.95, 0.99, 0.999}，每个模型训 20N tokens，共 642 次运行，仅在 RefinedWeb 上做；两阶段 Akima 插值取每个 N 的最优 (BS, LR)。拟合（Fig. 3 标签）：BS = 0.00037·N^0.703（R² 0.986），LR = 3.7·N^−0.36（R² 0.997）；取整用 **BS = 160·(N/108e6)^{2/3}，LR = 0.0047·(N/108e6)^{−1/3}**（batch 单位为 2048-token 序列）；DeepSeek 对应 BS = 0.00068·N^0.654、LR = 0.17·N^−0.25（batch 指数差 <0.05、预测差 <60%；LR 指数差 0.11、预测差 2–3 倍）。Table 4 取值：5M (LR 0.013, BS 20, β2 0.99)、7M (0.011, 28)、9M (0.011, 32)、15M (0.009, 44)、22M (0.008, 56)、28M (0.0074, 64)、37M (0.0068, 80)、57M (0.0059, 104)、84M (0.0051, 128)、108M (0.0047, 160)、149M (0.0043, 192，以上 β2 = 0.99)、220M (0.0038, 256, β2 0.95)、347M (0.0032, 320)、455M (0.003, 448)、611M (0.0027, 512)、901M (0.0024, 640)。
- **β2**："setting the AdamW β2 parameter to be 0.95 is suboptimal at smaller batch sizes (128 and below)"；只用 0.95 时 "for small models the optimal batch size saturates, resulting in a less consistent trend"（Fig. 16）。
- **验证**：901M / ~14B tokens，13 个 (LR, BS) 组合，规定值 (0.0024, 640) 最优 2.943（Table 7；相邻：LR 0.0012 得 2.947，BS 1280 得 2.955，BS 320 得 2.970，BS 160 得 3.050）。
- **理想逐 ρ 调参的影响（App. G.4）**：估计 "moves the estimate of the compute-optimal exponent by less than 0.032"；去掉最小两个 FLOP 值后 a = 0.489（实测）vs 0.5（理想）。超参在 N > 15M、ρ > 10 时距最优 loss <10^-2。
- **数据分析（§2.3, App. D）**：FLOP 网格 {1.25×10^16·2^i}_{i=0..11}；每逢 6N·D 越过网格值就在 160M held-out tokens 上评估；训练 loss 每 20 步记一次、用比例窗 p = 0.05 平滑并补偿 k/2 = 10 步滞后；对每个 C_i 用"加噪 + Akima 对数插值"的 bootstrap 求 N*(C_i) 的中位数与 log 标准差（下限 (1/3)·log√2），若 >50% 样本落在网格边缘则弃用该 C_i；幂律用 log 空间加权最小二乘（权 ∝ 1/σ²），CI 来自 bootstrap 分位数。噪声校准：验证集 100 个子样本 σ = 0.001–0.002；7 个种子的跨种子 σ 随 loss 对数线性增长，启发式取 RefinedWeb loss>7 为 0.05、loss<3 为 0.002（中间 log 插值），OpenWebText2 从 loss 6 的 0.1 到 loss 3 的 0.01。
- **最优 loss 趋势（§4.1, App. I）**：小算力下缩短 warmup、调超参各可降 loss 至多 0.5 nat，大算力下不显著；LR 衰减在大算力下持续有益。饱和幂律 L(C) = E + L0·C^−ℓ 只对调参实验外推良好，ℓ ≈ 0.1（"twice as large as the exponent found in Kaplan"）。"a predictable trend in L(N*(C), D*(C)) is an indicator of locally-optimal hyperparameters"。901M @ C+ ≈ 8×10^19 单次训练 L+ = 2.943 落在预测趋势上。
- **成本（§4.2, App. J）**：固定调度实验 1.54×10^20 FLOPs；逐预算 cosine 2.99×10^20（≈2 倍）；超参扫描 2.04×10^20；"in hindsight, we could have arrived at similar hyperparameters using only models of size at most 57M and a simple heuristic for choosing β2 based on batch size, which would have cost only 1.44×10^19 FLOPs"。全部实验 22.3K GPU hours、3.03×10^21 FLOPs（App. C）。

## 实验设定
- 框架 / 架构：OpenLM；decoder-only，qk-LayerNorm、SwiGLU、depth-scaled init、RoPE、xFormers、bf16 AMP；GPT-NeoX-20B tokenizer，词表 50432；seq 2048；嵌入与 head **不共享**；4 个注意力头；16 个模型 5.173M–901.7M（Table 2：深 3–30、宽 96–1504，d/l ∈ [32, 64]，N 按 ~√2 递增）。
- 数据：OpenWebText2（~30B tokens）与 RefinedWeb（~600B）；RefinedWeb 主实验无重复；超参扫描数据可能重复 ≤10 次、OWT2 大运行 ≤4 次（App. C）。
- 优化器：AdamW；z-loss 1×10^-4；independent weight decay 1×10^-4（PyTorch 的 wd 设为 1×10^-4/η）；β1 0.9；固定阶段 β2 0.95、LR 3×10^-3、batch 256 序列（Table 3）；调参阶段见 Table 4。
- 硬件：40GB A100，每次 4–32 卡，DDP + gradient checkpointing。
- **参数计法**（§2.1, App. B）：N = 全部线性层参数 = (3·d_FF + 4·d)·d·l + d·v，其中 d_FF = 256·⌊(255 + ⌊8d/3⌋)/256⌋，v = 50432；不含输入嵌入、含 head；N_exact（含 LayerNorm 等）与 N 差 ≤0.08%。N_eff = N + n·d·l（n = 2048）用于计入 attention；N_Kaplan = N − d·v。
- **FLOP 计法**：FLOPs(N,D) ≈ 6ND（Eq. 2.1）；计入 attention 则 6·N_eff·D，N_eff/N 在 1.1–1.2 间平滑变化（Table 2），换用 N_eff 后结论相似但 Chinchilla 算力处预测大约 16B（App. B, Fig. 7）；指出因果注意力只需一半 FLOPs，[25] 与 [15] 可能把 attention FLOPs 算成两倍；Hoffmann Approach 3 "appears to ignore the attention FLOPs and also count the embeddings parameters, i.e., setting N' = N + dv"。

## 函数形式与拟合方法
- 形式：N*(C) ≈ N0*·C^a，D*(C) ≈ D0*·C^b，ρ*(C) ≈ ρ0*·C^r（Eq. 2.1 之后）；D* = C/(6N*)，ρ* = C/(6[N*]²)。
- 流程：IsoFLOP 曲线 → bootstrap 估计 N*(C_i) 与 σ → log 空间加权线性回归 → bootstrap 分位数 CI（详见"方法要点"）。最优 loss 用饱和幂律 L(C) = E + L0·C^−ℓ，"by minimizing the Huber prediction loss for log L(C) over ℓ, log(E) and log(L0)"（App. I，仿 Hoffmann）。
- 全部拟合值：见 Table 1（a 与 R²、ρ* 范围）及 Fig. 1 标签（N*(C_C)）；BS/LR 幂律见上。**没有**拟合 L(N,D) 参数律。
- 敏感性 / 不稳定（原话）："the prediction becomes steadily more accurate and confident as compute increases"（Fig. 5）；"a saturating power law fits the optimal loss and extrapolates well, while extrapolating poorly for other experiments"；"we cannot determine with certainty which definition [N or N_eff] is more appropriate for predicting compute-optimal model sizes"；"If more than half of the bootstrap samples land at the edge of the grid, we omit the value of C_i"。

## 主要结论
1. Kaplan–Chinchilla 差异由三个因素造成，量级（RefinedWeb 的 a）：不计 head FLOPs +0.13（0.706 → 0.835）；固定长 warmup +0.10（0.602 → 0.706）；未按规模调 BS/LR/β2 +0.07–0.10（0.497 → 0.571 有衰减 / 0.602 无衰减）。合计从 0.50 到 0.84（Table 1, Fig. 1）。
2. LR 衰减**不是**原因：加 cosine 只把 a 从 0.602 降到 0.571（R² 0.993 → 0.998）；常数 LR 即可复现 a = 0.497、N*(C_C) = 77B（Chinchilla 70B）。
3. 最优 BS ∝ N^{2/3}、LR ∝ N^{−1/3}（Fig. 3）；batch ≤128 序列时 β2 必须升到 0.99；存在最优 batch，低于它性能反而下降（与临界 batch 理论相悖）。
4. warmup tokens = N（N–4N 皆近优，16N 明显差 0.054 nat，N/4 差 0.014）。
5. 调参与短 warmup 在小算力下各降 loss 至多 0.5 nat，大算力下作用消失；LR 衰减的收益随算力增大（Fig. 4）。
6. 常数 LR 的 scaling 实验成本约为逐预算 cosine 的一半（1.54e20 vs 2.99e20）。
7. 在 OWT2 上无需重调超参即得到相似结果（a = 0.518）；DeepSeek 在 OWT2 上得到 0.578，作者猜测源于数据重复。

## 失败模式与警告
- **不计输出头 FLOPs**：小模型算力低估至 90%，a 抬高 >0.1（§3.2, Table 2）。
- **warmup 按固定步数/固定 token 数**：小模型在 warmup 内就达到"最优"，D* 被抬高，a 抬高 ~0.1（§3.3, Fig. 2）；warmup 过短（N/4）亦略差。
- **固定大 batch（2^19）**：小模型只训几百步；必须按 N 缩放 batch 与 LR，并按 batch 调 β2（§3.5, App. G.3）；只用 β2 = 0.95 会让最优 batch 在小模型上饱和、趋势失真（Fig. 16）。
- **cosine 周期远长于预算**：Kaplan 的 131B 周期在其算力下衰减 <1.5%，等于没衰减（§3.4）。
- **N* 落在模型网格边缘**：>50% bootstrap 落边则弃用该 C_i；模型集必须让 IsoFLOP 曲线有内点极小（App. D）。
- **loss 噪声随 loss 增大而增大**，OWT2 比 RefinedWeb 噪 5–10 倍（App. D, Fig. 12）；小模型/早期点权重应更低。
- **最优 loss 曲线的曲率**：饱和幂律只在超参调好时可外推（App. I）；趋势不可预测本身是超参失调的信号。
- **超参扫描只在 ρ = 20 做**：理想逐 ρ 调参影响 <0.032（App. G.4），但作者仍列为局限。
- **数据重复**可能抬高指数（对 DeepSeek OWT2 0.578 的猜测，§5.1）。
- **attention FLOPs 口径**（N vs N_eff）会改变 Chinchilla 算力处的预测约 16B，且无法判定孰优（App. B）。
- 规模会掩盖这些问题（§5.2）：小算力实验（正是我们的区间）对这三个因素最敏感。

## 对我们实验的直接启示
**应该照搬（含数值）**
- N = 非嵌入 + 输出头；FLOPs 至少用 6ND，更好用逐项公式（含 head + attention）；报告 N、N_exact、N_eff、N_Kaplan 四列（Table 2 式）。
- warmup tokens = N（可取 1N–2N）；分支/cosine 运行再加 min(N, 20% 预算) 的上限。
- BS ∝ N^{2/3}、LR ∝ N^{−1/3}，以 108M 为锚：BS = 160·(N/108e6)^{2/3} 序列（2048 tokens）、LR = 0.0047·(N/108e6)^{−1/3}（其设定：independent wd 1e-4、z-loss 1e-4、qk-LayerNorm、untied head）；batch ≤128–192 序列时 β2 = 0.99。
- 模型网格按 ~√2 递增、d/l ∈ [32, 64]；FLOP 网格 2 倍递增；每个 C 至少 6–7 个模型且极小值在内点。
- 在最大规模做一次 Table 7 式的 ±2× LR/BS 十字验证。
- 用主干常数 LR 的中间点做 IsoFLOP/N*(C) 检查（Porian 证明这足以得到正确 a），用 Hägele 分支冷却点做 L(N,D) 拟合。
- 噪声校准：多种子（Porian 用 7 个）估 σ(loss)，拟合时按 1/σ² 加权。

**应该避免**
- 只在 20M 扫超参再"按规则"迁移——单点没有斜率；固定 batch 与 LR 跨规模；β2 固定 0.95。
- 固定步数 warmup（Hägele 的 300 步对 160M/0.1M batch 只有 0.19N tokens，落在 Porian 的"N/4 更差"一侧）。
- 数据重复；N* 落在网格边缘仍纳入拟合；在未调参情况下外推最优 loss 曲线。

**(b) 只在 20M 扫 LR 是否可行**：不可行。Porian 的迁移依赖在 6 个规模（5M–221M，核心 5M–108M，跨度 21×）拟合幂律并在 220M、901M 验证；其"事后最省"方案仍是 "models of size at most 57M"（网格内 8 个规模，5M–57M 跨度 11×）。最少做法：在 20M、40M、80M 三个规模做 LR × BS 网格（β2 ∈ {0.95, 0.99}），拟合斜率或固定 Porian 指数（−1/3、2/3）只拟截距，再在 160M 做 Table 7 式的 5–9 点十字验证；扫描预算取 20 tokens/param（G.4 表明逐 ρ 调参影响 <0.032）。若只能扫一个规模，至少固定 Porian 指数迁移并在 160M 验证，且在报告中注明。

**(c) warmup**：按 token 比例而非固定步数：warmup_tokens = N（Table 5 最优区 N–4N，2N 最好 3.528）。我们最短预算 10N，Porian 要求 D* ≥ 5× warmup 且 cosine 时 warmup ≤ 20% 预算 → warmup ∈ [N, 2N]，建议 **2N**（20M → 40M tokens，160M → 320M tokens；batch 0.25M tokens 时分别约 160 步与 1280 步）。主干只 warmup 一次，各分支共用。

**(d)** 见 08 笔记；Porian 口径：N 不含输入嵌入、含 head；FLOPs = 6ND 或 6·N_eff·D；对循环模型用实际执行层数计 attention 项 n·d·l_exec。

**(e)** 见 08 笔记；Porian 侧的补充：a 的估计随总算力"steadily more accurate"（Fig. 5），其 FLOP 网格 12 档、每档 6–7 个模型；对 β 的辨识需 D 跨度 ≥16×、≥5 档，并按噪声加权。

## 留白
- §5.2："Computational scale is a notable limitation, as well as a defining feature, of our results: our experiments are roughly on the scale of those in Kaplan et al. [30] but are substantially smaller than those of Hoffmann et al. [25]. Scaling may effectively mitigate each of the issues we identify: with scale, the contribution of the model head becomes negligible, any (fixed) warmup period eventually becomes reasonably long, and hyperparameter sensitivity decreases, as shown in Figure 5 and Figure 15."

This raises the concern that the hyperparameters we chose unfairly favor models trained for that particular token-to-parameter ratio..."
