## 摘要

循环（递归深度）Transformer 把一个由若干层组成的块连续跑 *r* 次。这要付出这个块 *r* 倍的计算量，但不增加参数。人们期望以此换来两个好处：循环模型应当表现得像一个更大的模型（参数效率）；推理时多跑几圈，应当不用写出思维链就能解更难的问题（潜空间推理）。我们用同一个模型家族和同一套训练配方检验了这两点。在我们的网格里，普通（不循环的）模型把 8 层各跑一次；报告里最常出现的循环模型，把中间 4 层跑 4 次，前后各有 2 层，所以一共跑 20 层。预注册的网格有 111 个语言模型（循环模型 10M–80M 参数，普通模型到 160M）。后续又加了一个 160M 的循环模型、更多的数据、一个合成任务和一些补充实验（S1–S10），每一项都在运行之前定好了方案。

下文的损失都以留出的网页文本（FineWeb-Edu）上每 token 的 nats 计。不同初始化种子之间，20M 普通模型的损失相差 0.014–0.024 nats。按种子配对并不能消除这种噪声，所以单个种子里 0.01 nats 的差别，在 10M–20M 处于噪声之内，只在 40M 分辨得出（第 2 节）。“每参数 token 数”是训练 token 数除以参数量 N。每个结果都标为预注册、预先写定（运行之前写在方案里）或探索性（看到数据之后才定）；其余术语见第 2 节。

### 在网页文本上

1. **参数相同时，从约 40M 起循环有帮助，数据越多帮助越大。** 参数和训练 token 数都相同时，中间块循环 4 次的模型，在 10M 时比普通模型*差* 0.02–0.10 nats，到 160M 时*好* 0.03–0.06 nats（每参数 10–40 个 token）。数据越多，优势越大：每参数 160 个 token 时，10M、循环 8 次的模型相当于用约 2.2 倍 token 训练的普通模型。换算成倍数，4 圈模型的每个参数，在 10–20M、每参数 10–20 个 token 时相当于 0.6–1.0 个普通模型参数，在 40M–160M、每参数 20–40 个 token 时相当于 1.26–1.46 个。

2. **训练算力相同时，普通模型赢。** 给普通模型同样的训练 FLOP（也就是让它看更多 token），在两种模型都用为普通模型调好的学习率时，普通模型损失为实测值的 258 次比较全是普通模型赢。差距随数据缩小，到最大的循环预算时为 0.01–0.05 nats。循环模型用试过的最低学习率时，两者在 10M、每参数 160 个 token 处打平，这是唯一一次普通模型没赢的实测比较。在 10M–40M 上为两种模型都重新调学习率（S1）后，规模趋势、数据趋势和同算力结论都不变；共用的学习率如果有偏差，也是低估了循环模型，在 10M 上约 0.02 nats。

3. **在 40M 上，循环的优势约有一半来自深度**（S10，3.7 节）。为了把深度和权重共享分开，我们训练了 18 层、参数量和循环模型大致相同的普通模型。这个更深的模型能拿回的循环优势份额（R，即两个倍数取对数之比，在三个预算上平均）为 0.50（95% 区间 0.41–0.62），落在方案为“一部分是深度，一部分是共享”划定的那一档，与方案的预测一致。循环模型对更深的模型的领先随数据增长。两边都用各自试过的最好学习率时（一个种子），在最短的预算上，深度拿回了全部优势。

4. **预注册的四个假设没有一个按原表述成立，预注册的定律也定不下一次循环的价值。** 预注册用每种循环方式一个指数来衡量这个价值，即 N_eff = N_once + r^φ · N_rec 中的 φ：φ = 0 时循环参数只算一次，φ = 1 时算 *r* 次。只有五个模型尺寸，把损失换算成等效参数的普通模型“尺子”拟合得很弱，φ 在主拟合中为 0–0.17，在联合拟合中为 0–0.41。截断反传没有降低 φ。循环中间块在原始损失上胜过循环整栈，但在 φ 上不一致。会饱和的形式并不比 r^φ 外推得更好；不论按训练算力还是部署算力，算力最优的都是普通模型（3.1 节）。按尺寸分别拟合，φ 从 10M 时的负值升到 160M 时的约 0.65，和倍数的趋势一样。约 130M–770M 的已发表同参数结果，换算成倍数也在相近的 1.2–1.6；按 Schwethelm 等的方式计 N，我们在 40M–160M 的局部指数（0.32–0.50）接近他们的 0.46。

5. **在文本上，推理时多跑几圈从不帮忙。** 用固定圈数训练的模型跑的是一个固定长度的程序，最后一圈是一次很大的“写出”。用截断反传训练的整栈（唯一探测过的截断模型）学到的则是一个周期性循环，用随机圈数训练的模型（和 Huginn 一样，但分布不同）收缩到一个不动点。它们在推理时多跑圈数都没有任何收益，学习率怎么取都一样。

### 在需要串行步骤的任务上

6. **循环一步一步地算这条链，多跑几圈就能解更长的链。** 任务是一串查表。探针显示，用 8 圈训练的循环模型每跑一圈推进一步。推理时多给圈数，它们能解比训练时更长的链：用 8 圈训练的模型，在 12 步题上用 16 圈时，准确率从 0.04 升到 0.83（用答案选出更多圈数中最好的一个时为 0.86）。增益随长度减弱，到约 16 步就没有了。普通模型一出训练范围就失败，即使执行深度相同、参数多达 4.4 倍；固定圈数的模型按训练圈数运行时也是如此。在适合普通模型的学习率下，12 个循环运行里有 10 个在同样的训练步数内没有学会训练范围（准确率 0.49–0.98；S2）。

7. **写出来的思维链在训练范围内更便宜，超出范围就失败**（S5）。把链作为 token 写出来的普通模型，在训练范围内全对：每个种子、每个试过的学习率都是 1.000，推理算力不到循环模型按训练圈数运行时的三分之一。在每一个更长的链上，它们都接近随机水平，36 层的也一样。超过 8 步的题，写出来的链在前三个 token 之内就断了：8 层模型 97–98% 的题如此，36 层模型 68–86% 的题如此。这个任务里链越长、提示也越长，所以这更像是没能推广到更长的输入；这个比较说不清，在输入长度固定时，写出来的思维链能否延长。停顿 token 没有任何作用。

8. **大多数模型能自己决定何时停。** 模型自己的置信度就是一条不用看答案的停法：阈值 0.99 时，对用 4 圈、8 圈或随机圈数训练的模型，它拿回了多跑圈数收益的 97–98%；对用 2 圈训练的模型，它甚至比最好的固定圈数还好（S8；这条规则是我们比较了几条之后选的）。用圈数 = 步数训练的模型延长得最远（12.8 步），但“等状态不再变化就停”的规则停不下它，因为它从没被训练到最后一步之后。训练时让它多跑几圈，它就能保住中间值，靠置信度停下时在 12 步题上达到 0.93 的准确率，代价是少延长约一步（S9）。

### 部署时的代价

9. **部署时，循环要付出解码时间和显存**（S3，S6）。每个执行的层各存一份 KV 缓存时，解码时间和缓存都随跑的层数增长。损失相同时（两种模型都按每参数 40 个 token 训练），中间块循环 4 次的模型最多省下 19% 的权重显存，但 KV 缓存是普通模型的 2.2–2.4 倍，每 token 解码时间是 2.4–2.5 倍，批 32 时峰值显存约 1.6 倍。在多圈之间共用 KV 缓存，本可去掉这项成本的大部分；但在 20M 上的一次测试里，固定圈数的模型共用缓存后损失 0.09–0.17 nats，比它们靠循环从普通模型那里赢来的还多，是这份收益的 2.2 到 7.4 倍。这些收益只来自一个种子，而在 20M 上，循环减普通模型的差距在种子之间相差 0.032–0.045 nats，所以这些倍数只是粗略的估计。

### 解读

在这项研究里，再跑一遍同一个块，只有在任务需要串行步骤、而且循环被训练去迭代时，才起到测试时算力的作用。在这些规模的网页文本上，剩下的是一份参数效率上的收益，它随规模和数据增长，代价是解码时间。我们对两个场景的差别的理解是：当模型的错误来自串行步骤太少、而不是缺少知识，而且循环能跑得更久而不破坏状态时，多跑的圈数才有用；部署时要用上它们，模型还需要一个何时停的信号。训练得当时，链任务满足这些条件；在这些规模的网页文本上，看不到第一类错误的迹象。两个场景太少，不足以检验这个解释。第 9 节列出了能检验它的后续实验。

## 1. 研究动机

循环 Transformer 把一个由若干层组成的块重复使用多次：例如 Universal Transformers [1]，以及近来的 Huginn [2]、Ouro [3] 等。人们期望它有参数效率：循环模型应当表现得像一个更大的普通模型，当部署主要受显存或带宽、而不是计算量限制时，这一点很重要。人们还期望它能做潜空间推理：如果循环是在对一个问题反复迭代，那么测试时多跑几圈，就应当能解更难的题，而不需要写出思维链。

这两种说法都很难从已有文献中核实。各项研究的数据、分词器、训练配方和模型家族都不同，也很少报告种子。真正关心的那个量——多一圈值多少——通常是从单次拟合里读出来的。我们则用同一套配方训练了一组受控的尺寸阶梯。我们在训练之前写下了假设和分析方法（[预注册](preregistration.md)，2026-09-23 冻结），并记录了之后的每一处改动（[偏离记录](deviation-log.md)）。文本上的结果没有检验第二个期望，于是我们构造了一个需要串行步骤的任务，冻结了它的设计和预测，用同样的方式跑了它。

### 相关工作

关于一次循环值多少，Kaplan 等 [4, 附录 D.2, 图 17] 已经发现，重复使用参数的循环 Transformer"在参数量相同时稍好，但把重复使用算进去、按 FLOP 比较时稍差"。我们的结果在这两个方向上都与之一致。

我们检验的等效参数形式 N_eff = N_once + r^φ·N_rec 来自 Schwethelm 等 [5]，在循环前后各留两层不共享的做法也来自他们。他们在 FineWeb-Edu 上、最多 8 圈、没有报告重复的种子、只计非嵌入参数，估计 φ = 0.46（95% 区间 0.41–0.53）。他们还发现，只穿过后一半圈数的截断反传，会把 φ 从 0.45（他们在相同预算上重新拟合的基线）降到 0.38。那个比较把省下的 FLOP 用来多训练 token，因此混合了等 token 和等 FLOP 两种口径。我们的预注册就是为了能与他们比较而设计的（我们的 N 还计入了输出头）。它的 H1 检验的就是这一发现，并把这两种口径分开；在这里没有得到支持。前段–核心–后段的布局本身，包括 (2, 4, 2) 的分法和把状态与前段输出拼接后做线性映射的输入注入，来自 Huginn [2]。

其他研究在别的设置下测量一次循环的价值。Parcae [6] 发现，在参数和 token 数相同（算力不同）时，循环能降低困惑度。Lee 等 [7] 发现，按相同 FLOP 比较时，没有稀疏层的循环模型的 scaling 比不循环的差。Chen 等 [8] 发现，在单 epoch 训练中，把更深模型的权重绑在一起大约要多付一个固定倍数的算力；而在重复数据上，最优圈数随算力增长。在 Ouro [3] 的一个受控附录里，同深度的普通模型在每一次比较中都胜过循环模型；在 [11] 中，单纯的递归在相同算力下的验证损失也比普通模型差。

无论是没有稀疏层的循环模型，还是循环的混合专家模型，一个有上界的形式外推到 16 圈时都比 r^φ 更准 [9]；我们最多 8 圈的数据分不出饱和形式和 r^φ（H3）。一个 1.4B 的循环模型训练了 310B token（210B 预训练，即在 16B token 的语料上约 13 遍，再加 100B 中期训练），在全部 12 个基准上胜过参数和数据相同的普通模型，代价是每 token 约 4 倍的训练算力，而在三圈时推理算力相同的 3.9B 普通模型，在每个基准上都领先或持平 [10]。这些研究都没有在多个种子下把模型规模和每参数 token 数分开变化，这正是本研究主要增加的东西（3.3 节）。

用随机圈数训练的 Huginn [2]，在定性的例子里，潜在轨迹会收敛到不动点或轨道，或者朝一个方向稳定漂移。Logan [12] 在一个小型深度递归模型中看到逐 token 收敛到不动点，与我们在随机圈数下看到的一致（第 4 节）。Huang 等 [13] 发现，固定深度、完整反传的训练会使多圈之间无法共用 KV 缓存；在我们的 20M 模型上，共用缓存让每个从循环得益的模型损失 0.09–0.17 nats，截断反传也一样（S6）。Saunshi 等 [14] 发现循环模型的收益集中在推理任务上，这可能与我们在数学和代码上更大的收益有关。

循环网络多跑几次迭代，就能解比训练时更难的题，也会"想过头" [15, 16]。圈数随输入而定的循环 Transformer 能推广到更长的输入 [17]。Kohli 等 [18] 表明，测试时多给圈数，递归深度 Transformer 能外推到更深的事实组合链：训练到 12 跳，可达 14–19 跳。参数相同或 FLOP 相同的普通 Transformer 做不到。Zhang 等 [19] 发现，循环每圈解决的位置数与训练长度除以训练圈数成正比（在一个依任务而定的范围内）；输入长度不变时，测试时多给的圈数能救回靠后的位置。我们的合成任务结果与这两项都一致。在这两项之外，我们对每个中间值都做了探针，测量了学习率如何影响任务能否在训练预算之内学会，在同一批存档上比较了几种不看答案的停法，还在同样的题目上把循环与思维链 [27] 和停顿 token [28] 作了比较，各自的推理算力按层次数计。

推理时，除非共用缓存，循环模型的 KV 缓存和解码时间都随圈数增长。[20] 中两圈约需两倍的 KV 显存和 1.96 倍的延迟。[21] 中，普通循环模型在 2、3、5 圈时每步解码分别慢 2.3、3.4、5.7 倍。在多圈之间共用缓存的方案已经有了 [3, 13, 21]：Ouro [3] 只在解码时共用，[21] 用第一圈写的缓存。本研究只在训练好的模型上事后共用（S6），没有带着共用缓存训练。

## 2. 实验设置

### 本报告的术语和标记

每个结果都带三种标记之一。*预注册*指假设和判定规则于 2026-09-23、任何训练开始之前冻结（[预注册](preregistration.md)）。*预先写定*指写在一份在相应运行之前冻结的方案里：[合成任务设计](synthetic-reasoning-design.md)，或三份补充实验方案 [S1–S3](supplementary-experiments.md)、[S4–S9](supplementary-experiments-2.md)、[S10](supplementary-experiments-3.md) 之一。*探索性*指看到数据之后才定下的。对冻结文档的每一处偏离，都在[偏离记录](deviation-log.md)里注明了日期。完整数字在[结果汇总](results.md)，下文引作"结果汇总 §x"。

损失以留出的 FineWeb-Edu 上每 token 的 nats 计，另行说明的考卷除外。三个初始化种子之间，20M 普通模型的损失在每参数 10–40 个 token 时相差 0.014–0.024 nats（10M 和 40M 为 0.004–0.008），20M 各循环单元相差 0.003–0.07。按种子配对并不能消除这种噪声。种子和宽度都相同的训练，在共有的层上从相同的权重开始，读的数据也相同；但同一种子的 4 圈模型和普通模型之间的差距，在种子之间仍相差 0.005–0.020 nats（10M）、0.032–0.045（20M）和 0.003–0.005（40M）（`fit/paired_noise.py`）。单个种子里 0.01 nats 的差别，在 10M–20M 处于这种噪声之内，在 40M 才分得出来；网格在 10M–40M 的结果都是三个种子的平均。"每参数 token 数"是训练 token 数除以 N，"40N"指每参数 40 个 token。N 计非嵌入参数加输出头。

- *单元*是一种循环配置：哪些层循环、循环几次（*r*）、反传是穿过全部圈还是截断。
- *档*是一个模型尺寸。
- *中间块*循环 8 层中间的 4 层，前两层和后两层不共享；*整栈*循环全部 8 层。
- *普通模型*指不循环的模型。
- *同参数*比较，是把循环模型和同尺寸、用同样 token 训练的普通模型比。*同算力*比较，是把它和训练 FLOP 相同、也就是看了更多 token 的普通模型比。

预注册提出了四个假设：

- H1：截断反传降低 φ，在等 token 和等 FLOP 两种口径下都如此。
- H2：循环中间块的 φ 高于循环整栈。
- H3：φ 随 *r* 饱和。
- H4：按训练算力计，算力最优的 *r* 较小；按部署算力计则更大。

## 3. 循环在文本上值多少

### 3.1 预注册假设的判定

| 假设 | 判定 |
|---|---|
| H1 截断降低 φ | 不支持。中间块 0.00 对 0.13（方向与预测一致，区间重叠）；整栈 0.17 对 0.00（方向相反）。等 FLOP 口径下相同。 |
| H2 中间块 > 整栈 | 依口径而异。φ 的结果不一；在执行深度相近时（36 层对 32 层、20 层对 16 层）比较原始损失，24 次比较中 24 次偏向中间块。 |
| H3 随 r 饱和 | 不支持。按预注册的外推检验，饱和形式用 10M–40M 预测 80M 比 r^φ 更准（0.0085 对 0.0096），用 20M–80M 预测 10M 略差（0.0203 对 0.0200）；数据分不出两种形式的高下。 |
| H4 算力最优的 r | 无论按训练算力还是部署算力，最优的都是普通模型（r = 1）。 |

检验过程中还发现，截断反传对循环 4 次的整栈有帮助，每个尺寸上都是如此。在 20M、每参数 10 个 token 时，整栈循环 4 次的模型截断时达到 3.646，不截断时为 3.783（三种子均值）；循环 8 次时，截断在 10M–20M 上反而略差。另外，在 10M 上，按三个预算平均，比普通模型好的循环单元只有 r = 8 的整栈循环。

截断和整栈循环还带来了损失尖峰。111 次训练中有 30 次至少出现过一次尖峰：其中 25 次用了截断反传，另外 5 次是不截断、循环 8 次的整栈。有一次训练崩溃了。在一项后续实验中，把学习率减半，尖峰就消失了。

### 3.2 指数 φ，以及从实测普通模型读出的倍数

φ 需要一把尺子：用普通模型拟合出的那条公式，它告诉我们一定数量的参数能换来多低的损失。在我们五个普通模型尺寸上拟合时，尺子的不可约损失落在下界上，参数指数 α = 0.054，远低于常见的 0.3。五个尺寸无法把 E、A 和 α 分别定下来。对全部训练做联合拟合得到 α = 0.267，φ 也更大（0–0.41，而不是 0–0.17）。预注册的 φ 值照原样报告（[结果汇总 §3](results.md)），但下面的结论建立在不需要尺子的量上。作为对照，Schwethelm 等 [5] 用他们自己的尺子得到 φ = 0.46；尺子的参数这样难以确定，不同研究之间的 φ 绝对值很难相互比较。图 2 是固定尺子、在每个尺寸上分别拟合的 φ（探索性）。

<p align="center"><img src="../code/results/figures/fig2_phi_by_rung.png" width="70%"><br><em>图 2：四种循环方式在每个尺寸上分别拟合的 φ，预注册的尺子固定不变，允许取负值（探索性）；点线是每种循环方式的预注册值。三种循环方式的 φ 随尺寸上升，截断反传的整栈则随尺寸下降，所以每种循环方式只用一个值，就把不同的情形平均在了一起。</em></p>

实测的普通模型本身也可以当尺子，不必给它们拟合任何定律。对每个循环模型，在用同样 token 训练的实测普通模型之间插值，就能找出损失相同的普通模型大小 N*（[结果汇总 §5.17](results.md)；探索性）。倍数 N*/N 于是表示循环模型的每个参数（含输出头）相当于多少个普通模型参数。

对中间块循环 4 次的模型，倍数从 10–20M、每参数 10–20 个 token 时的 0.6–1.0，升到 40M–160M 时的 1.15–1.5。规模每翻一倍，倍数乘以 1.21；每参数 token 数每翻一倍，乘以 1.14（循环 8 次时为 1.16）。这些值用到了补充实验 S4 续训的普通模型：10M 和 20M 的普通模型分别训练到每参数 640 和 320 个 token（3.4 节；[结果汇总 §5.18](results.md)）。倍数为 1 时，循环模型和同大小的普通模型一样好。按对 log M、log N 和 log（每参数 token 数）拟合的平面，每参数 20 个 token 时，倍数约在 N = 35M 处达到 1（在 20M 和 40M 两个模型之间）。每参数 80 个 token 时，倍数约在 N = 12M 处达到 1，比最小的模型还小：叫作 10M 的那个模型，N 是 15.4M。实测点在每参数 80 个 token 时与平面一致（10M 模型为 1.04，平面给出 1.05），在 20 个 token 时却更早达到 1：20M 模型（N = 26.8M）已经是 0.99，平面给出的是 0.93。

在 40M–160M、每参数 20–40 个 token 时，倍数稳定在 1.26–1.46。换算成局部指数 φ_loc（定义为 N* = N_once + 4^φ_loc · N_rec），像 Schwethelm 等 [5] 那样不计输出头时为 0.32–0.50，接近他们的 φ = 0.46；计入输出头时为 0.35–0.52。约 130M–770M 的已发表同参数结果 [3, 6, 14] 换算过来，大多也在相近的 1.2–1.6；[14] 里的小块每参数训练了 750–1500 个 token，最高约到 2。Ouro 的 778M 模型每参数约 26 个 token，从图上读出来高于 1.75；它的 53M 模型每参数看了约 377 个 token，价值却仍不如它的参数 [3]。770M 以上只有界限：一些下界，以及 [10] 中 1.4B 模型的 1–2.8。

一次循环的价值随规模和数据而变。预注册给每种循环方式只定一个值，相当于把两种情形平均在了一起：一种是每参数 token 数少的小模型，循环模型的每个参数最多约值一个普通模型参数；另一种是较大的模型，每个参数约值 1.4 个。价值随每参数 token 数变化，是一个"循环 × 数据"的效应，已发表的等效参数规律里没有这一项。在那些规律里，价值依赖圈数（混合专家模型还依赖稀疏度），但不依赖训练 token 数 [5, 9]。

我们还把已经训完的 10M 中间块循环 4 次和 8 次的模型续训到每参数 80 和 160 个 token，20M 的续训到 80（图 4）。对中间块单元，数据每翻一倍，优势就再增加 0.02–0.03 nats，看不到饱和的迹象。换算成普通模型要追平循环模型所需的数据量，10M 中间块循环 8 次的模型从每参数 10 个 token 时的 0.86×（种子 42）升到 160 时的约 2.2×。两个种子分别是 1.95× 和 2.49×，是从 S4 延长到 640 的普通模型曲线上读出来的；S4 之前，160 以外的普通模型损失靠外推，这个倍数是 1.68×。20M 的在 80 时达到约 2.0×（1.93× 和 2.07×），整栈循环的方向也一样。

### 3.4 训练算力相同时的比较

同尺寸、同 token 时，循环训练比普通模型训练花的算力多。为了在同算力下比较两者，我们把每次循环训练的训练算力换算成普通模型用同样算力能看到的 token 数，再从实测的普通模型曲线上读出普通模型的损失。在共用的学习率下，凡是能实测的比较，都是普通模型更好。

S4 之前，320 次比较中有 221 次能实测，全部是普通模型赢，至少好 0.016 nats；另外 99 次需要普通模型曲线之外的损失。那里的真值由两种外推夹在中间。按最后一段实测的斜率外推偏向普通模型：在一个去掉每条实测普通模型曲线最后几个预算的回测里，外推一个翻倍时，它把普通模型的损失估低了 0.023–0.036 nats。对每条曲线拟合幂律则偏向循环，外推一个翻倍时，把普通模型的损失估高了 0.006–0.027 nats。用幂律时，99 次里有 6 次是循环更好，最多好 0.021 nats，全在每参数数据最多的地方（[结果汇总 §5.17](results.md)）。

S4 随后把 10M 普通模型续训到每参数 640 个 token，20M 的续训到 320 个，于是 320 次比较里有 258 次成了实测。在共用的学习率下，这些比较全是普通模型赢，实测的差距大约落在两种外推的中间。其余 62 次比较仍要用外推的普通模型损失，43 次在 40M–160M，19 次在 10M–20M，几乎都属于第三个种子，它的普通模型曲线只到每参数 80 个 token。

| 循环单元（尺寸，每参数 token 数） | 训练算力，相对同尺寸普通模型 | 同参数同 token 的差 | 同算力的差 |
|---|---|---|---|
| 中间块 r = 4（10M，160N） | 2.2 倍 | −0.033 | +0.016 |
| 中间块 r = 8（10M，160N） | 3.7 倍 | −0.051 | +0.034 |
| 中间块 r = 4（20M，80N） | 2.2 倍 | −0.051 | +0.022 |
| 中间块 r = 8（20M，80N） | 3.8 倍 | −0.064 | +0.052 |

主考卷上循环损失减普通模型损失，种子 42、43 的均值；负数 = 循环更好。同算力时，普通模型训练的 token 数是循环模型的 2.2–3.8 倍（[结果汇总 §5.18](results.md)，S4）。

每参数数据越多，差距越小。10M 中间块循环 4 次时，差距在 40N 为 +0.119，80N 为 +0.062，160N 为 +0.016；20M 从 20N 到 80N 依次为 +0.138、+0.075 和 +0.022。

给循环模型用更低的学习率，会改变其中一次比较。S1 用普通模型学习率的 0.35 倍训练了 10M 中间块 r = 4 的模型，这是它试过的最低值；学习率降到这里时损失仍在下降，所以最优学习率没有被夹住。在每参数 160 个 token 处，这个模型与普通模型平均持平，两个种子分别为 −0.011 和 +0.005，即在一个种子里循环模型领先 0.011 nats。这是本研究中第一个普通模型没有赢的同算力比较。每参数数据再多时它会不会变成循环赢，没有测。在同参数时循环有帮助的地方，它能用更少的参数或更少的数据达到同样的损失；在测过的范围内，它不能用更少的算力做到这一点。

### 3.5 学习率

所有循环语言模型都沿用了普通模型的学习率。在 20M、每参数 10 个 token 上，一项检查为十个循环单元找过更好的学习率，判定规则在运行前就写定了，结果没有找到。它试了普通模型学习率的 0.5、0.71 和 1 倍，十个单元里有九个在 1 倍最好，而 1 倍是所试范围的上沿，所以更高的学习率并没有被排除。

补充实验 S1 随后在 10M、20M 和 40M 上，为普通模型和中间块循环 4 次的模型都重新调了学习率，预算为每参数 10–40 个 token（10M 还有 80 和 160）。它试了普通模型学习率的 0.5–1.41 倍，事先定好的边界规则要求时再加 0.35 倍；用一个种子（20M 用两个），因而它的差距与 3.3 节的三种子均值略有出入。普通模型的最优学习率在 0.004 nats 以内一直是 1×：在 40M 上，0.71× 在每参数 40 个 token 时只好 0.001 nats，在 80 时好 0.004（普通模型的运行到每参数 80 个 token）。

对循环模型来说，在 20M–40M 上，共用的学习率最多把它的优势低估了 0.005 nats；但在 10M 上，从每参数 20 个 token 起，循环模型偏好 0.5× 及更低的学习率，用这些学习率能好约 0.02 nats（最多 0.024）。两边各用最优学习率时，每参数 40 个 token 的差距从 10M 到 40M 依次为 −0.005、−0.031 和 −0.055 nats，而同样的种子在共用学习率下为 +0.015、−0.031 和 −0.050。规模趋势小了一些，但按事先写定的规则仍然成立；10M 的数据趋势则更大了，从每参数 10 个 token 时的 +0.082 变到 160 时的 −0.059。

同算力下，重调后的 11 次比较里普通模型赢了 10 次，其中一次（40M、每参数 40 个 token）用的是外推的普通模型损失。剩下的一次在 10M、每参数 160 个 token，起初用的也是外推的普通模型损失。S4 实测后，它是 −0.011，即循环模型领先 0.011 nats；加上第二个种子（+0.005），两者平均持平（3.4 节；[结果汇总 §5.16、§5.18](results.md)）。

### 3.6 逐 token 的收益和其他考卷上的收益

逐 token 看，网页文本上的收益是一个幅度小、范围广的整体下移：大约一半的 token 变好，收益集中在难 token 上的程度，也没有超出两个普通模型种子之间本来就有的差异。

<p align="center"><img src="../code/results/figures/fig5_gap_by_exam.png" width="80%"><br><em>图 5：每参数 40 个 token 时，四个循环单元在四个考卷（FineWeb-Edu、SlimPajama、FineMath 和代码）上的循环模型损失减普通模型损失，尺寸为 20M、40M 和 80M（种子均值；80M 只有一个种子；探索性）。收益在数学和代码上最大，种子之间的噪声也是在这两个考卷上最大。</em></p>

在数学和代码上收益更大（图 5），平均约为 3 倍和 7 倍（各单元分别为 1.5–7 倍和 4–11 倍），但这两类考卷上种子之间的噪声也大 10–100 倍。补充实验 S7 表明，代码考卷对数据顺序（我们的各个种子共用同一个数据顺序）比对初始化还要敏感，数学考卷则不然。在分布内，20M 上同一个初始化分别用数据流中三段互不重叠的数据训练，主考卷损失变动 0.003–0.010 nats，是初始化种子之间差距的 0.1–0.5 倍，所以本报告里的种子区间不需要另加说明。在代码考卷上，数据顺序让损失变动 0.21–0.69 nats，最多是初始化差距的 7 倍，循环减普通模型的配对差在不同顺序下还会变号。

由于在这个规模上，初始化和一次训练碰巧看到哪些文档都会大幅改变它的分布外损失，分布外考卷在这里不能用来做精细比较（[结果汇总 §5.18](results.md)，S7）。这些考卷上还有一个异常没有得到解释：在 160M、每参数 40 个 token 时，一个循环模型种子在分布外考卷上比另一个差 0.2–0.6 nats，而两者在主考卷上的损失相同。

### 3.7 深度还是权重共享（S10）

尺子里的普通模型全是 8 层，而中间块循环 4 次的模型要执行 20 层，3.2 节的倍数量到的就可能是同样大小下更深的好处，而不是共享的好处。在十亿参数以下，同样大小时更深更窄的模型更好 [33]；而在同样大小下，形状在很宽的范围内变化，对损失的影响都很小 [4]。

补充实验 S10（[方案](supplementary-experiments-3.md)，2026-10-27 在任何运行之前冻结）用 18 层、参数量和循环模型大致相同的普通模型检验了这一点：20M 时为 18 × 320（N = 28.1M），40M 时为 18 × 448（N = 51.2M）。它们用网格的配方、数据、预算和三个种子训练，倍数 M_deep 与循环模型的 M_loop 从同一把尺子上读出。方案事先定好了判读：在 40M 上，R = log M_deep / log M_loop 在三个预算上的平均，就是同样大小、深度相近的普通模型能拿回循环模型优势的份额。

| 40M | 10N | 20N | 40N |
|---|---|---|---|
| 18 层普通模型的损失 | 3.397 | 3.232 | 3.119 |
| 循环模型（中间块，r = 4）的损失 | 3.394 | 3.217 | 3.090 |
| 循环模型对 18 层模型的领先（各种子） | 0.003（0.004、0.004、−0.001） | 0.015（0.017、0.018、0.010） | 0.029（0.030、0.032、0.026） |
| M_deep | 1.10 | 1.11 | 1.11 |
| M_loop | 1.15 | 1.26 | 1.34 |
| R | 0.67 | 0.46 | 0.36 |

在 40M 上，三个预算平均的 R 是 0.50（95% 区间 0.41–0.62），落在方案判读为"一部分是深度，一部分是共享"的那一档，和预测一致。深度买到的那部分不随数据增长，循环模型的优势却随数据增长。20M 上的结果只作描述，因为那里 M_loop 接近 1。这个尺寸上的 18 层模型宽度只有 320，比同样大小的 8 层模型还差（M_deep 0.84–0.94）。在那里，循环模型每参数 40 个 token 时的优势（M_loop 1.16）完全不能用深度解释。

18 层模型的学习率检查用种子 42，试了规则学习率的 0.71 倍和 1.41 倍。在 40M、10N 时，1.41 倍好 0.014 nats，触发了方案的规则（20N 和 40N 时它分别好 0.006 和 0.001，20M 上则是规则学习率最好）。和 S1 一样，这里也报告了两种模型各用试过的最好学习率时的判读。在这些学习率下，深的模型在 10N 时领先循环模型 0.010 nats（M 为 1.37 对 1.18）；20N 和 40N 时 R 为 0.56 和 0.34（同一个种子在规则学习率下为 0.45 和 0.37）。三个预算平均，最好学习率下的 R 是 0.94，落在方案判读为"优势大部分是深度效应"的那一档。这个平均是 10N 撑起来的，那里 log M_loop 最小；方案规定主判读仍用规则学习率。这些判读来自结果出来之后才写的脚本（`fit/supp3_best_lr.py`），因为结果之前写好的分析脚本只标出了这种情况，没有去算。深的模型最好的学习率是试过的最高一档，所以它的最优值没有被夹住。

此外，18 层模型每 token 的训练算力约为循环模型的一半（40M 时 406M 对 835M FLOPs）；同算力时，在它的曲线不用外推就够得着的地方，它领先 0.11–0.19 nats。方案的三条预测里，第一条是 R 在 0.25–0.75 之间，成立了。第二条是 40M 时 18 层模型比 8 层模型好 0.01–0.03 nats，三个预算里两个成立（0.007、0.016、0.020）。第三条是规则学习率与最好的学习率相差不到 0.01 nats，六个预算里五个成立（[结果汇总 §5.19](results.md)）。

在 40M 上，同参数时循环在文本上的优势大约一半来自深度。两边都用各自试过的最好学习率时，在最短的预算上，深度拿回了全部优势（只试了一个种子）：更深的模型在那里领先 0.010 nats，是规则学习率下这个差距在三个种子之间极差的两倍。在 20M 上，深度一点也解释不了这份优势；在两个尺寸上，深度都拿不回随数据增长的那部分。

## 4. 循环块在文本上算的是什么

我们对训练好的模型逐圈做探针，用三种方式读每一圈之后的状态：直接用模型自己的输出层读（即 logit lens），在输出层前面加一个训练过的线性变换再读，以及用一个训练过的线性头读（图 6）。

<p align="center"><img src="../code/results/figures/fig8_loop_probes.png" width="95%"><br><em>图 6：16 圈中每一圈之后的主考卷损失，有三种读法：直接用模型自己的输出层（等于跑这么多圈），在输出层前面加一个训练过的线性变换，或者用一个训练过的线性头。各小图依次是 20M、40M 和 80M 用 8 圈训练的中间块，以及 80M 用截断反传（k = 4）训练的整栈；种子 42，每参数 32 个 token 时的主干存档。超出刻度的读数落在图框上方；图 7 画出了 80M 模型的完整范围（图中标题称它为“fig 6”）。中间块要到第 8 圈才达到低损失，不过经训练过的线性变换读时，第 4 圈已经接近；截断反传的整栈每 4 圈回到一次低损失。</em></p>

固定圈数（r = 8）时，循环跑的是一个固定长度的程序。用训练过的线性变换来读，第 4 圈之后的状态给出的损失已经和最终损失相差在 0.1–0.2 nats 以内，第 5–7 圈几乎没再增加什么。最后一圈是一次幅度很大的非线性移动，把状态改写成输出层所期望的形式：37–47% 的 token 直到这一圈才定下预测。推理时少跑或多跑圈数都会破坏模型（图 7）。这在 20M 和 40M 的全部三个种子上，以及 80M（一个种子）上都成立。

截断反传（整栈，k = 4）得到的则是一个周期为 4 的循环：状态每 4 圈回到几乎同一个点，所以模型在 4、8、12 或 16 圈时都能工作，再多跑也没有收益。

<p align="center"><img src="../code/results/figures/fig6_depth_curve.png" width="60%"><br><em>图 7：四个 80M 循环模型在推理时跑 1 到 16 圈的主考卷损失；星号标出各自的训练圈数。用完整反传训练的模型只在训练圈数下达到低损失。截断反传的整栈在图中画出的每个 4 圈周期的倍数上都能工作（4、8 和 16 圈；图中没有画 12 圈）。</em></p>

如果每个训练步都从 1–8 中随机抽取圈数（Huginn 也随机抽取圈数，但分布不同），模型学到的是向一个不动点的收缩。推理圈数从 1 到 32，它的损失在约 4 圈之后都是平的（图 8）。模型对圈数鲁棒，但在标称的 8 圈上比固定 r 训练差 0.05 nats，与普通模型打平。

<p align="center"><img src="../code/results/figures/fig10_random_r_depth.png" width="55%"><br><em>图 8：20M 中间块在推理时跑 1 到 32 圈的主考卷损失（每参数 32 个 token 时的主干存档），训练时用 8 圈，或在每个训练步从 1–8 中随机抽取圈数（完整反传或截断反传）；虚线是训练 token 数相同的普通模型。用随机圈数训练时，模型从约 4 圈起就是平的，也不比普通模型好；用 8 圈训练时，它只在 8 圈时工作。</em></p>

学习率会改变这些曲线的形状：学习率越低，损失随推理圈数变化的曲线越平。这一点最先出现在循环学习率检查的 20M 模型上。S1 在 10M、20M 和 40M 上（中间块循环 4 次，每参数 32 个 token 时的存档）证实了它：在 4–16 圈之间，学习率为普通模型 0.5 倍时，损失的变化幅度是 0.36–0.77 nats，1.41 倍时是 3.4–4.6 nats。学习率越低，迭代越接近收敛；但在文本上，不论学习率多少，跑得比训练圈数多，从来没有带来好处。

## 5. 一个需要串行步骤的任务

### 5.1 任务和条件

预测网页文本的下一个词很少需要许多串行步骤，所以文本很少给循环迭代的理由。我们构造了一个需要串行步骤的任务（[设计](synthetic-reasoning-design.md)，2026-10-09 冻结）。

每道题给出一个起始值和一串 d 次查表，每步查一次，例如 `25 ; LUT 7 ; LUT 3 ; LUT 19 ; … =>`。每个 LUT 是 32 个定义在 0–96 上的固定随机函数之一，模型必须在一次前向计算中输出最终值。两次查表复合起来是 1024 种任意函数之一，跳步的模型就得记住急剧增长的复合表。这个任务奖励一步一步地算，不过和任何满足结合律的复合一样，原则上也存在更浅的解法。

模型在 1–8 步的题上训练，测试到 24 步。训练时题目是随机抽的，所以短题会重复出现（一步题只有 3,104 种），但超过 8 步的链在训练中从未出现。任务在正式运行之前改过两次，两次都在任何条件之间的比较之前：链长均匀混合时模型学不会，于是加了课程学习；模运算链又学得太慢，于是把运算换成了固定的查找表。

我们把 8、20 和 36 层的普通模型与一个 8 层的循环模型（执行 2 + 4×r + 2 层）比较。循环模型分别用 r = 2、4 或 8 圈训练，或用随机圈数训练，或用与链的步数一样多的圈数训练（圈数 = 步数）。每个条件都用只按分布内准确率扫描选出的学习率，各有 5 个种子。后来又在 S5 里加了两个条件（5.6 节）：把中间值写成思维链的普通模型，以及带停顿 token 的普通模型。S9 另加了一种循环训练方式，即圈数 = 步数再随机多跑几圈（5.5 节）。原计划还有一个对照任务，叫指针追踪，后来去掉了：它没有做过预试，而在按链任务校准的配方下，试过的四个条件都没有学会它。

### 5.3 与普通模型的比较，以及推理时多给圈数

参数相同时，圈数越多，能解的链越长：4.2 → 6.4 → 8.0 → 9.0 步。执行深度相同的普通模型，参数是循环模型的 2.4–4.4 倍，却少解 1–1.6 步（20 层的那个没有完全学会训练范围）。

没有一个普通模型能超出训练范围（图 9）：12 步时它们的准确率是 0.02–0.06。固定圈数的循环模型按训练圈数运行时也止步于此（0.03–0.05），但多给圈数后能达到 0.64–0.86，随机圈数模型达到 0.83，圈数 = 步数的模型达到 0.96。

<p align="center"><img src="../code/results/figures/fig14_synthetic_inference_loops.png" width="95%"><br><em>图 10：用 8 圈训练的模型（左）和用 1–8 随机圈数训练的模型（右）在推理时跑 4、8、16 或 32 圈，准确率随链长的变化（五个种子的均值；色带为范围；阴影为训练范围）。虚线是 36 层普通模型，深度和 8 圈相同。圈数越多，能解的链越长，但准确率仍随长度下降。</em></p>

推理时多跑圈数能解更长的链（图 10）。用 8 圈训练的模型在 8 圈时能解 9 步，在 16 或 32 圈时能解约 11 步，但收益有限：16 步时它的准确率是 0.37。用随机圈数训练的模型同样有收益：16 步时，准确率从 8 圈的 0.08 升到 16 圈的 0.49。用圈数 = 步数训练的模型，跑与链的步数一样多的圈数时，在 10 到 16 步的每个长度上都比它自己跑 8 圈时准 0.34–0.95（种子平均）；9 步时，8 圈已经能解出这条链，收益只有 0.03。预先写定的预测 P3(c) 按这个差值判定（5.8 节）。

### 5.4 对中间值的探针

<p align="center"><img src="../code/results/figures/fig15_synthetic_probes.png" width="95%"><br><em>图 11：每个中间值 x_j 第一次能以至少 0.5 的探针准确率解码出来的那一圈（左：循环模型，种子均值）或那一层（右：普通模型，每个种子一条线）。用 8 圈或圈数 = 步数训练的模型每圈算一步，其余循环模型一圈算不止一步，普通模型算得晚；只能解码出 x_1 和答案的普通模型种子，在最后一层显示为单独的一个点。</em></p>

在每一圈之后，我们针对每个中间值 x_j 训练一个线性探针（图 11）。每个探针读提示中第 j 步附近的三个位置，取最好的一个；只读一个位置的探针，曾漏掉某个种子存放在别处的中间值。为了衡量模型多跑圈数时能不能保住已经算出的值，我们用保持度：一个值首次出现之后，它在后面各圈中探针准确率的最低值，再对所有值取平均。

在用 8 圈训练的模型里，每一圈算一步：x_j 大约在第 j 圈出现（x_8 在第 8 圈；5 个种子都是每步 1.0–1.1 圈），而且每个值之后一直可以解码（保持度 0.96）。用圈数 = 步数训练的模型同样每圈算一步，在跑自己的 d 圈期间也保住了这些值（这 d 圈内的保持度为 0.92），但跑得更久就会丢掉。它差不多需要 d 圈，是因为它在训练时从没在最后一步之后继续循环过，固定圈数的模型则有过。

用较少圈数训练的模型，把更多的步塞进每一圈：r = 4 时每圈约 1.6 步，r = 2 时约 2.4 步，方向与 Zhang 等 [19] 的预测一致。普通模型算得晚，36 层中大约从第 21 层才开始。20 层和 36 层模型的 10 个种子里有 5 个，在各步的位置上看不到第一个之后的任何中间值：其中 4 个只看得到 x_1（探针准确率 0.50–0.74）和最后一层的答案，1 个什么都看不到。

### 5.5 不看答案的停法

多跑的圈数要在部署时有用，前提是不看答案也能定下跑几圈。冻结的设计为圈数 = 步数的模型规定了一条状态规则：答案位置的状态在相邻两圈之间变化不到 2% 就停，最多 32 圈。每次运行都算了它，但直到 2026-10-15 才报告（[结果汇总 §5.15](results.md)）。对用 4 圈或 8 圈训练的模型，它在 12 步上拿回最好固定圈数收益的约 80%，在 16 步上拿回 60–70%，跑 11–19 圈，而且不影响训练范围。外推最远的圈数 = 步数模型却靠它停不下来：跑过 d 圈后，它的状态仍在变，在每个长度上都停在错的圈数（准确率 0.02–0.08）。它能外推最远，部分是因为题目里写明了步数，也就给了它该跑的圈数。

S8 在正式运行的 25 个循环模型存档上比较了另外几条不看答案的规则，规则和阈值都在它的方案里定好；方案写于状态规则在这些存档上的结果出来之后，在比较之前冻结。规则在一套题上选，在另一套题上报告。其中一条规则用模型自己的置信度：最高概率达到阈值就停，阈值为 0.99，r = 2 时为 0.9；它是 Fan 等 [17] 的最大置信度规则的提前停止版本。在能停下来的规则里，除了 r = 4，它在每个条件下都最好；r = 4 时，阈值更低（0.5%）的状态规则与它持平（12 步时 0.816 对 0.815）。对 S9 模型，这条状态规则略好一些（0.94 对 0.93，五个种子都是如此）。这两种情况下，状态规则跑的圈数都多得多（27 对 9，24 对 14）。

阈值取 0.99 时，对用 4 圈、8 圈或随机圈数训练的模型，置信度规则在 12 步上拿回了最好固定圈数收益的 97–98%。在训练范围以内的题上，它用的圈数比这些模型训练时的圈数还少。它把圈数 = 步数的模型拉到 0.76，代价是在范围内丢掉 6–7% 的题。"预测不再变化就停"常常停在一个已经不再变化的错误答案上，因为固定圈数模型的读出要到最后一圈才转过来。对各种圈数的预测做多数投票不算停法，也从没超过最好的固定圈数：在方案的规则选中它们的地方（r = 4、r = 8 和随机圈数），它们与最好的固定圈数相差在 0.013 以内；在 r = 2 和圈数 = 步数上则差得很远。

S9 改的则是训练，让同一个模型既能外推得远，又能停下来：圈数 = 步数的模型在最后一步之后再随机多跑 0–4 圈来训练。这样它跑 16 圈时也能保住中间值（保持度 0.04 → 0.91），外推少了约一步（90% 线上为 11.6 对 12.8；多给圈数时为 12.2）。用置信度规则时，它在 12 步题上达到 0.93，同时仍能解出范围内 0.998 的题，而且在这些范围内的题上用的圈数少于 d，不过 12 步时用了 14 圈。按冻结的状态规则，它能不能停好因种子而异（平均 0.52：两个种子能停，两个不能，第五个部分管用）。方案预先写下的三种判读都不涵盖这一结果。训练它每个训练步的算力约为圈数 = 步数模型的 1.4 倍。

| 模型 | 自身圈数 | 最好的固定圈数（看答案选） | 状态变化 < 2% | 置信度 ≥ 0.99（r = 2 时为 0.9）；括号内为平均圈数 |
|---|---|---|---|---|
| 循环 r = 2 | 0.05 | 0.62 | 0.45 | 0.70（8.3） |
| 循环 r = 4 | 0.04 | 0.83 | 0.65 | 0.81（9.2） |
| 循环 r = 8 | 0.04 | 0.86 | 0.71 | 0.84（17） |
| 随机圈数 | 0.77 | 0.83 | 0.73 | 0.83（14） |

12 步链上的准确率，S8 报告集上的种子均值（[结果汇总 §5.18](results.md)，S8 和 S9）。

在正式运行里，外推得远和停得好来自不同的训练方式。S9 的训练方式两者兼得，代价是外推少了约一步。

### 5.6 与写出来的思维链和停顿 token 的比较

补充实验 S5（[结果汇总 §5.18](results.md)）把链任务交给了另外两种普通模型。一种把中间值写成 token，有 8 层的（与循环模型一样大）和 36 层的（与循环模型的执行深度相同）；另一种是带 d 个停顿 token [28] 的 8 层模型。每种各 5 个种子，学习率的选法与其他条件相同。思维链模型的每个中间值都有损失监督，循环模型和普通模型只在答案上有监督，这一差别方案里事先写明了。

| 模型 | 参数量 | 范围内（1–8 步） | 12 步 | 16 步 | 每道 12 步题的层次数 |
|---|---|---|---|---|---|
| 普通 8 层，写思维链 | 6.5M | 1.000 | 0.014 | 0.015 | 408 |
| 普通 36 层，写思维链 | 29.0M | 1.000 | 0.017 | 0.013 | 1836 |
| 普通 8 层，d 个停顿 token | 6.5M | 0.566（解 4 步） | 0.015 | 0.012 | 416 |
| 普通 8 层，只答最终值 | 6.5M | 0.62（解 4.2 步） | 0.064 | 0.048 | 320 |
| 循环 r = 8，8 圈 / 16 圈 | 6.6M | 0.998 | 0.036 / 0.827 | 0.033 / 0.285 | 1440 / 2720 |
| 循环，圈数 = 步数，跑 d 圈 | 6.6M | 1.000 | 0.957 | 0.366 | 2080 |

种子均值；推理算力按处理的 token 上的层次数计（12 步题的提示有 40 个 token；思维链模型带 KV 缓存再生成 12 个）。

在训练范围内，思维链全对：每个种子、每个试过的学习率都是 1.000，而只答最终值的 8 层模型只能解 4 步。它也更便宜：12 步时，它的推理算力不到循环模型按训练圈数运行时的三分之一，408 次层通过对 1440 次（真正解出 12 步链的 16 圈要 2720 次）。

超出训练范围，它就完全不能延长。12 步时 8 层模型为 0.014，36 层为 0.017，接近 0.010 的随机水平；循环模型在同样的长提示上为 0.83–0.96。一项诊断显示，提示里的表一超过 8 张，链就在写出的前三个 token 之内断掉：8 层模型 97–98% 的题如此，36 层为 68–86%。8 层模型写出的第一个 token，在 9 步题上 81% 是对的，在 12 步题上 57% 是对的；36 层模型几乎总是对的。即使给定正确的前文，前两个之后的 token 也大多是错的（8 层模型在多数位置上的准确率为 0.04–0.10）。这与输入长度上的泛化失败相符，也就是 Transformer 在比训练时更长的输入上的已知弱点 [31, 32]，而与沿链逐步累积错误不符。循环模型读的是同样变长的提示，却仍能延长；它们为什么能延长，我们没有检验。不过这个任务的提示随步数变长，所以这个比较回答不了：在输入长度不增长的任务上，写出来的链能不能延长。针对长度泛化的补救措施不在方案之内。

停顿 token 没有任何作用（解 4 步，和不加时一样）。在这个任务上，循环和写出 token 哪个更好，要看题目有多长：像训练题那样的题，写出 token 更便宜，也全对；更长的题，循环是这里唯一能延长的额外计算形式。

### 5.7 链任务上的学习率

上面所有循环模型都用 1.25e-4–2.5e-4 的学习率训练，比为 8 层普通模型（独立层数相同）选出的学习率 1e-3 低 4–8 倍。（这些是嵌入层和输出层的学习率；隐层的学习率按独立层数缩放。）

学习率扫描只用了一个种子（种子 1）。在扫描里，同样的 r = 8 结构在 1e-3 下，训练范围就学得很差：同样训练 16000 步后，准确率为 0.54，2.5e-4 时则为 0.999。它也没有逐步推进的前沿：和第 4 节的语言模型一样，它只在恰好 8 圈时工作。对扫描的全部存档做探针，看到的是同样的分化。对循环 r = 8，学习率不超过 5e-4 时有逐步推进的前沿（1.25e-4 和 2.5e-4 时大约每圈一步，5e-4 时约 1.5 圈一步），1e-3 和 2e-3 时没有。循环 r = 4 和随机圈数模型也是如此。

补充实验 S2 在完整的训练长度上检验了这一点。它在 5e-4 和 1e-3 下，把方案认定能外推的四个循环条件各用 3 个种子完整训练了 32000 步。（方案依据一个后来更正了的数字，没有纳入 r = 2；其实 r = 2 也能外推，到 8.6 步。）1e-3 下，12 个运行里仍有 10 个没学会训练范围（准确率 0.49–0.98）。5e-4 下，12 个里有 8 个学会了，它们大多和正式运行外推得差不多远：循环 r = 8 超出训练范围 2.7 步，正式运行为 3.2 步；圈数 = 步数为 4.0 步，正式运行为 4.8 步。例外是随机圈数，学会的两个种子外推 2 步，正式运行为 4.2 步。

学习率高主要是让循环模型在给定的步数内学不会这个任务。模型一旦学会，学到的大多是同一种可以延伸的算法（[结果汇总 §5.16](results.md)）。

### 5.8 预先写定的预测

冻结的设计写了五条预测（[结果汇总 §5.15](results.md)）：

- P1（参数相同时，圈数越多，能解的步数越多）方向成立，但 r = 8 没有达到 16 步。
- P2（同深度的普通模型至少一样好）按原表述不成立，但差距不大：1–1.6 步，r = 8 时在 P2 允许的范围内。
- P3（推理时扩展）分三部分。P3(a) 对了一半：少于训练圈数时，固定 r 的模型确实变差，与预测一致；但多跑圈数*没有*让 4 圈和 8 圈的模型变差。P3(b) 不成立，不过偏差的方向对循环有利：预测不会受益的随机圈数模型，在长链上受益了。P3(c) 成立：圈数 = 步数的模型跑 d 圈时，在 10 到 16 步的每个长度上都胜过它自己跑 8 圈；从 10 步算起，是看过结果之后才定的。
- P4（只有圈数 = 步数的模型探针表是对角的）对了一半，因为按一个看过结果之后才定的对角比例定义，固定 r 的模型的探针表也是对角的。如果按"一个值在哪一圈解码最准"来读，两者的比例分别是 0.625 和 0.425，P4 就会成立。
- P5（差距比文本上大得多）成立。

补充实验的预测里，S5 三条成立一条，S8 五条成立两条，S9 四条成立三条；判读见[结果汇总 §5.18](results.md)。

## 6. 部署时的代价

参数相同时，中间块循环 2、4、8 圈，每 token 的训练 FLOP 分别是同尺寸普通模型的 1.4–1.5 倍、2.2–2.4 倍和 3.7–4.1 倍，每 token 的解码时间分别是 1.5 倍、2.4–2.6 倍和 4.5–4.6 倍。这些是在一张 RTX 4090 上用 bf16 测的，解码带 KV 缓存，每个实际执行的层各存一份缓存，这样解码时的计算就和训练时一样（补充实验 S3，[结果汇总 §5.16](results.md)）。

更公平的是在损失相同时比较，对照的是在每参数 40 个 token 时达到同样损失的普通模型（在普通模型尺寸之间插值）：

| 单元 | 尺寸 | 权重显存 | 每 token 的 KV 缓存 | 解码时间，批 1 | 峰值显存，批 1 | 峰值显存，批 32 |
|---|---|---|---|---|---|---|
| 中间块 r = 2 | 20M–80M | 0.93–1.03× | 1.43–1.51× | 1.45–1.49× | 0.99–1.15× | 1.21–1.24× |
| 中间块 r = 4 | 20M–160M | 0.81*–0.96× | 2.20–2.41× | 2.37–2.47× | 0.98*–1.19× | 1.57–1.58× |
| 中间块 r = 8 | 20M–80M | 0.83–0.92× | 4.01–4.23× | 4.27–4.56× | 1.08–1.34× | 2.29–2.40× |
| 整栈 r = 4 | 20M–80M | 1.03–1.11× | 4.02–4.26× | 4.00–4.11× | 1.18–1.84× | 2.32–2.41× |
| 整栈 r = 8 | 20M–80M | 0.81–0.85× | 6.96–7.23× | 7.57–7.91× | 1.27–1.50× | 3.38–3.91× |

循环模型相对同损失普通模型的倍数；\* 160M 超出了最大的普通模型（外推）。

损失相同时，循环模型最多省下 19% 的权重显存（中间块 r = 4：从 20M 到 160M 依次为 4%、14%、17% 和 19%），而解码时间和 KV 缓存大致要按多执行的层数付出。批 1 时，更大的 KV 缓存抵消了权重上省下的部分：中间块循环 4 次（r = 4）的模型在 80M–160M 时峰值显存低 1.5–2.4%，在 20M–40M 时反而更高（最多 1.2 倍）。序列一多，KV 缓存就让循环模型需要更多显存，批 32、1k 上下文时为 1.2–3.9 倍。在这个范围内，大多数循环模型在损失相同时需要的权重显存更少（整栈循环 4 次是例外，为 1.03–1.11×），没有一个能少用解码时间，峰值显存也只在批 1、80M–160M 时才降下来。在权重主导显存的情形下，比如在大得多的模型上一次只跑一条短上下文的序列，省下的会更多；这种情形我们没有测。

在多圈之间共用 KV 缓存，能去掉 KV 缓存和显存上的大部分代价，但去不掉多出来的解码时间。我们测的方案里，每个独立层占一份缓存：循环核心的每一层只留一份缓存，供所有圈共用，每一圈读的都是前面各 token 在它们最后一圈写下的键和值；循环之外的层仍各用自己的缓存。补充实验 S6 把它用在训练好的 20M 模型上（[结果汇总 §5.18](results.md)）：

| 模型（20M，种子 42，32N 主干） | 推理圈数 | 缓存份数，完整 → 共用 | 完整缓存的损失 | 共用缓存的损失 | Δ |
|---|---|---|---|---|---|
| 中间块 r = 8，不截断 | 8 | 36 → 8 | 3.443 | 3.534 | +0.091 |
| 中间块 r = 8，截断反传 | 8 | 36 → 8 | 3.451 | 3.591 | +0.140 |
| 中间块 r = 8，随机圈数 | 8 | 36 → 8 | 3.496 | 3.496 | 0.000 |
| 中间块 r = 4，不截断 | 4 | 20 → 8 | 3.442 | 3.611 | +0.170 |
| 中间块 r = 4，不截断，学习率减半 | 4 | 20 → 8 | 3.425 | 3.525 | +0.100 |

在这次只用一个种子的测试里，这个规模上每个从循环得益的模型，共用缓存后赔掉的都比它的收益多，约为收益的 2.2 到 7.4 倍：赔掉 0.09–0.17 nats，而在同一存档、同一批 token 上，它们相对普通模型的收益是 0.019–0.046。这些收益只来自一个种子，而在 20M 上，循环减普通模型的差距在种子之间相差 0.032–0.045 nats（第 2 节），所以这些倍数只是粗略的估计。共用缓存之后，这些模型每一个的损失都会比同尺寸的普通模型更高。截断反传在这里也没有让缓存变得可以共用，这与 Huang 等 [13] 的发现相反。只有用随机圈数训练的模型能免费共用；它们的循环块收缩到不动点（第 4 节），相对普通模型也没有任何收益。

在固定圈数的模型里，学习率低的赔得少（0.100 对 0.170），这和“朝收敛的方向训练，或者直接带着共用缓存训练，才能得到可共用的缓存”相符，不过只凭一对运行还证明不了。Monea 等 [21] 用另一种方案预训练循环模型：只有第一圈写缓存，之后各圈读它，同时各自保留一个短窗口；他们发现这样不损失质量。这两种做法我们都没有测。

## 7. 实用结论

- 如果受限的是参数，而不是数据、算力或延迟，就用循环。同参数下的优势随模型大小和每参数 token 数增长（3.3 节）。同算力、共用学习率时，每次实测比较都是普通模型更好，差距随数据缩小。循环模型用试过的最低学习率时，两者在 10M、每参数 160 个 token 处平均持平（3.4 节）；这个最低的学习率也是试过的学习率里最好的，所以循环模型在那里的最优学习率没有被夹住。部署时，循环要按执行的层数付出解码时间和 KV 缓存（第 6 节）。
- 用循环之前，先试同样大小、更深的普通模型。在 40M 上，用 18 层代替 8 层，花约一半的训练算力，就拿到了循环模型约一半的优势；在每参数 10 个 token、学习率调好时，拿到了全部。只有随数据增长的那部分优势才需要循环（3.7 节）。
- 要用循环，就循环中间块，并且不截断反传。执行深度相近时，中间块循环在每一次比较中都胜过整栈循环；30 次出现过损失尖峰的训练里，25 次用了截断反传（其中 16 次是整栈循环），而 100 次循环运行里只有 40 次用了截断反传。在 10M 的一项后续实验里，把学习率减半就消除了尖峰。
- 在文本上先用 r = 4，并在目标规模上评估。在 40M–80M，r = 8 的效果与 r = 4 差不多，训练算力却约为 1.75 倍，解码时间和 KV 缓存约为 1.8 倍。模型越大、每参数 token 数越多，一次循环越值钱，所以小规模的消融实验会低估它的价值。
- 不要指望在文本上得到测试时扩展：固定圈数训练出的模型只在训练圈数下工作，随机圈数训练让模型对圈数鲁棒，但多跑圈数也不会更好（第 4 节）。
- 循环模型的学习率要单独调，小规模和需要逐步计算的任务尤其如此。在文本上，普通模型的学习率在 20M–40M 上与循环模型的最优值很接近，在 10M 上则差了 0.02 nats。在链任务上，用普通模型的学习率时，多数循环运行在同样的训练步数内没有学会训练范围（5.7 节）。
- 在推理时扫一遍圈数，看模型能不能用上更多的圈。在文本上，我们的模型都不能；在链任务上，多跑圈数时准确率保持得住的模型，也能用这些圈解更长的链。只在训练圈数下工作的模型，在这些圈之内仍可能是逐步计算的，圈数 = 步数的模型就是这样；探针能把两种情况分开（5.4 节）。
- 除了参数，也要算上 KV 缓存和延迟。损失相同时，循环模型最多省下 19% 的权重显存，批 32 时峰值显存却是 1.2–3.9 倍。多圈共用缓存让固定圈数的模型赔掉的比它们靠循环赢来的还多，在一个种子上是收益的 2.2 到 7.4 倍（第 6 节）。
- 在需要串行步骤的任务上，按需要的长度在循环和思维链之间选。训练范围内，思维链更便宜，也全对；超出范围，只有循环能延长（5.6 节）。如果模型得自己停，就用它的置信度：阈值 0.99 拿回了多跑圈数的几乎全部收益（阈值更低的状态规则在 r = 4 时与它持平，对 S9 模型还略好一些，但跑的圈数多得多）。用圈数 = 步数再随机多跑几圈来训练，得到的模型既能外推，又能靠置信度停下，五个种子都是如此（5.5 节）。

## 8. 更正

运行结束后，我们分几轮核对了结果和文档，两次外部审阅（2026-10-14 和 2026-10-28）又找出了一些错误。每一处更正都在[偏离记录](deviation-log.md)里注明了日期；这里列出的，是改变了某个判定、某种判读或某个主要数字的更正。

在链任务上，P3(b) 起初是按能解的最长链判定的；按设计写定的准确率之差，随机圈数模型能从多跑的圈数中受益。P3(a) 对了一半，P3(c) 成立，而我们原先分别判为不支持和部分成立。S8 的五条预测成立两条，我们原先报告的是一条。设计写定的一条停法算过了，却直到 2026-10-15 才报告。我们撤回了“圈数 = 步数的模型会覆盖算出的值”和“置信度总是最好的停法”这两个说法，并把“多跑的圈数需要一个何时停的信号”限定在部署上。

在文本上，H3 的外推检验原先把 160M 留在了训练集里；按预注册重做后，r^φ 不再在两个方向上都更好。联合拟合的 φ 更正为 0–0.41。同算力的结论原先没有说明，320 次比较里有 99 次依赖一种偏向普通模型的外推。最大预算处的等效数据倍数约为 2.2 倍和 2.0 倍；我们原先报告的是 1.7 倍和 1.65 倍，那是在 S4 延长普通模型曲线之前算的。S3 里批 1 的峰值显存原先多算了一份 KV 缓存。共用缓存的代价起初是拿别的存档上的收益来比的；改用同一存档上单个种子的收益来比，它是收益的 2.2 到 7.4 倍。第 2 节原先说，种子相同的两次运行之间相差 0.01 nats 是分得出来的；但这种配对差距在种子之间变化太大，在 10M–20M 分不出来，只在 40M 才分得出来。

## 9. 局限

- 规模：五个尺寸按大致的非嵌入参数量命名为 10M–160M（叫作 10M 的模型 N = 15.4M），16k 词表，远小于部署循环语言模型时的 1B+ 规模。scaling 趋势可能会弯折；我们有五个尺寸，80M 只有一个种子，160M 只有一个循环单元。
- 语言模型只在一个数据来源（FineWeb-Edu）上训练，没有文档被看两次，所以没有覆盖多 epoch 的情形，而循环在那里可能更重要 [8, 30]。
- 部署成本只在一种 GPU 上、对最大 160M 参数的模型测过，并且每个实际执行的层各存一份 KV 缓存。权重主导显存的更大模型没有测；多圈之间共用缓存，只是作为事后改动，在不带共用缓存训练的模型上测过（S6）。
- 学习率只为 10M–40M 上的一个循环单元重新调过（S1），用一个种子（20M 用两个）。其余单元以及 80M、160M 用的都是普通模型的学习率。在链任务上，选学习率的标准饱和了（圈数 = 步数的模型在三个学习率下都是 0.9999），平局时取了最低的学习率，而协议没有规定这一点。4 圈、随机圈数和 S9 的模型在试过的最低学习率上最好，所以它们的最优值没有被夹住；模型能外推多远，对学习率很敏感。
- 尺子里的普通模型都是 8 层。S10 的 18 层普通模型只有两个尺寸、每个尺寸一种形状（20M 时很窄）；它们的学习率只用一个种子检查过，40M 时最好的是试过的最高一档。
- 合成任务的证据来自一个任务族和 6.6M 参数的模型，外推长度在种子之间差别很大，原计划的指针追踪对照也去掉了（5.1 节）。
- 与写出来的推理的比较（S5：思维链 [27] 和停顿 token [28]）只覆盖一个合成任务、6.5M–29M 参数的模型和一种训练方式。这个任务的提示随步数变长（3d + 4 个 token），所以思维链模型在训练范围外的失败，是对更长输入的泛化失败，而循环模型在同样的提示上应付得了。在输入长度不随步数增长的任务上，写出来的链能不能延长，没有测。思维链模型的每个中间值都有监督，循环模型只在答案上有监督；思维链模型没有得到任何长度泛化方面的帮助，连续思维 [29] 也没有试。
- 种子只改变初始化，S7 除外，它在 20M 上改变了数据顺序。在分布内，数据顺序的影响小于初始化；在分布外，它在代码考卷上大于初始化，在 SlimPajama 考卷和数学考卷上与初始化相当或更小。
- 320 次同算力比较中，有 62 次依赖外推的普通模型损失（3.4 节）：43 次在 40M–160M，19 次在 10M–20M，几乎都属于第三个种子，它的普通模型曲线只到每参数 80 个 token。其余 10M–20M 的普通模型曲线现在分别到每参数 640 和 320 个 token（S4）。
- 我们考虑过四项后续实验，并在 2026-10-17 决定不做：输入长度固定的第二个合成任务族、文本上执行深度和宽度都与循环模型相同（因而参数更多）的普通模型对照（S10 的 18 层模型保持的是参数量）、80M 再加两个种子，以及在推理为主的文本上训练的普通模型和循环模型。没做的每一项，都让上面的某一条局限留了下来（[路线图](roadmap.md)、[论文计划](paper-plan.md)）。
